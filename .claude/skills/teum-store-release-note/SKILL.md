# teum-store-release-note 스킬

`teum-pr-creator` 스킬(STEP 1.5-6)이 생성한 상세 릴리즈 노트(신규 기능/개선 사항/버그 수정
카테고리, PR 링크 포함)를 입력으로 받아, Google Play 등 스토어 등록란에 바로 쓸 수 있는
초간결 릴리즈 노트로 압축하는 스킬.

---

## 실행 조건

- `main`으로의 PR이 **실제로 병합 완료된 시점**에 사용한다. 병합 전에는 사용하지 않는다.
- 직전에 `teum-pr-creator`가 생성한 상세 릴리즈 노트(제목 + 클립보드에 복사된 본문)가 있어야 한다.
  없다면 대상 버전 범위(예: `PREV_TAG..현재 태그`)를 먼저 확인해 상세 릴리즈 노트부터 생성하도록 안내한다.

---

## STEP 1 — 사용 여부 확인 (항상 먼저 묻는다)

`main` PR 병합이 확인되면, 요약 릴리즈 노트를 생성하기 전에 반드시 아래 형식으로 사용 여부를 먼저 묻는다.

```
main으로의 PR이 병합되었습니다.

방금 생성된 상세 릴리즈 노트를 기반으로 스토어 등록용 3줄 요약 릴리즈 노트(ko-KR/en-US)를
만들까요?

[y] 생성   |   [n] 건너뛰기
```

`n` 또는 거부 응답 시 아무 것도 생성하지 않고 종료한다.

---

## STEP 2 — 요약 생성

`y` 응답 시, 상세 릴리즈 노트의 "새로운 기능 / 개선 사항 / 버그 수정" 섹션 각각을 정확히 1줄로
압축한다. 카테고리는 최대 3개(🆕/🔧/🐛)이며, 해당 카테고리에 내용이 없으면 그 줄은 생략한다.

### 압축 규칙

- 각 카테고리의 여러 항목을 쉼표로 나열되는 명사구 형태로 압축한다. 문장형 서술(~했습니다)은 쓰지 않는다.
- 상세 릴리즈 노트에 포함된 PR 링크는 **여기서는 포함하지 않는다** (스토어 노출용 텍스트이므로).
- 한 줄은 공백 포함 대략 60자 내외로 유지한다. 항목이 많으면 사용자 임팩트가 큰 핵심 3~4개만 선정한다.
- 이모지·줄 순서는 항상 `🆕 → 🔧 → 🐛` 고정.

### 출력 형식 (예시)

```
<ko-KR>
🆕 SSE 스트리밍 기반 학습 요약 생성, PDF OCR 진행률 표시, Firebase Analytics 전면 도입
🔧 목표 완료 UX, 닉네임 입력, 쿠폰 사용 흐름 개선
🐛 인증 화면 전환 뒤로가기 오작동 등 다수 버그 수정
</ko-KR>
<en-US>
🆕 Added SSE streaming-based learning summaries, PDF OCR progress tracking, and full Firebase Analytics integration
🔧 Improved goal completion UX, nickname input, and coupon usage flow
🐛 Fixed several bugs, including incorrect back navigation during auth screen
</en-US>
```

### 다국어 처리

- `<ko-KR>` 블록을 먼저 작성한 뒤, 이를 자연스러운 영어 문장으로 의역해 `<en-US>` 블록을 작성한다
  (직역 금지 — 영어권 사용자가 읽었을 때 어색하지 않은 문장으로).
- 두 블록의 줄 수·이모지·순서는 항상 동일하게 유지한다.

---

## STEP 3 — 출력 및 클립보드 복사

이 결과물은 짧으므로(최대 6줄) PR 본문과 달리 **터미널에 그대로 출력**하고, 동시에 클립보드에도 복사한다.

```bash
cat <<'EOF' | pbcopy
<ko-KR>
🆕 ...
🔧 ...
🐛 ...
</ko-KR>
<en-US>
🆕 ...
🔧 ...
🐛 ...
</en-US>
EOF
```

출력 후 아래 안내를 덧붙인다.

```
위 내용이 클립보드에 복사되었습니다. 스토어(Play Console 등)의 언어별 릴리즈 노트란에 붙여넣어 주세요.
```

---

## 안전 규칙

- `main` PR이 병합되지 않은 상태에서 요청받으면, 병합 여부를 먼저 확인하고 병합 전이면 생성하지 않는다.
- 압축 과정에서 원본 상세 릴리즈 노트에 없는 내용을 추가하지 않는다(과장·창작 금지).

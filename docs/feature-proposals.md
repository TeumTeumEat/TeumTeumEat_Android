# 틈틈잇(TeumTeumEat) 신규 기능 제안서

> **상태: 실기기 QA 1회 반영 완료 — 단, 인간 사용자의 진짜 주관적 피드백은 여전히 미확보**
> 2026-07-24 실기기 QA(로컬 Claude Code가 adb/uiautomator로 기기를 직접 조작)와 외부 UX 리뷰 아티클(uibowl.io, 틈틈잇을 직접 사례로 분석한 글)을 반영했습니다. QA는 사용자 본인이 손으로 조작한 것이 아니라 **AI가 조작한 것**이므로, 화면 흐름·데이터 정합성·타이밍 실측 같은 **기능적 사실은 신뢰도 높게 반영**했지만 "동기부여가 되는가", "하루를 놓쳤을 때 어떤 기분인가" 같은 **진짜 인간의 주관적·감정적 반응은 아직 확보되지 않았습니다.** 이 문서에서 "[AI 관찰]"로 표시된 부분은 AI의 추정이며 실제 인간 페르소나의 목소리가 아님에 유의하세요. 현재 구현 상태의 사실 기반 명세는 [`feature-spec.md`](./feature-spec.md)를 참고하세요.

## 1. 페르소나 정의

**김서현 (가상, 29세) — IT 스타트업 마케터**

- 듀오링고(외국어), 챌린저스(습관 인증 기반 보상), 토스(자산관리 리포트), 인프런/클래스101(직무 학습) 등 자기개발·학습 앱을 상시 여러 개 병행 사용.
- 출퇴근 지하철, 점심시간, 자기 전 등 자투리 시간에 짧게 학습하는 패턴을 선호 — **틈틈잇의 "5분 이내" 컨셉과 니즈가 정확히 맞아떨어지는 핵심 타깃**.
- "꾸준함"에 대한 강박이 있어 스트릭이 끊기면 크게 좌절하고, 그 좌절이 종종 앱 이탈로 이어짐.
- 콘텐츠를 소비하는 것 자체보다 **"내가 실제로 얼마나 성장했는지"를 수치·그래프로 확인**하고 싶어함.
- 학습 앱을 여는 계기는 대부분 알림이며, 알림이 형식적이면 곧 무시하게 됨.
- 초보자용 커리큘럼보다 **"내가 고른 목표"를 스스로 관리**해주는 앱을 선호.

## 2. 페르소나 워크스루 & 갭 분석

> ⚠️ 아래는 코드 기반 가설 + 2026-07-24 AI 조작 실기기 QA 결과를 결합한 것입니다. "[AI 관찰]"은 AI의 추정이며 서현(페르소나)이 실제로 느꼈을 감정이 아닙니다. **진짜 인간 사용자의 주관적 반응은 여전히 열린 항목**입니다(맨 아래 참고).

서현의 시점에서 온보딩 → 홈 → 요약 → 퀴즈 → 결과 → 목표 관리 흐름을 따라가며 짚은 인상입니다.

**긍정적으로 볼 지점**
- 온보딩에서 카테고리/PDF 중 학습 방식을 스스로 고를 수 있어 "내가 만든 목표"라는 느낌을 초반부터 준다.
- 요약+퀴즈 한 세트가 짧게 설계되어 있어 "5분 이내" 약속이 화면 구조상 지켜진다 — **QA로 실측 확인**(디버깅 지연 포함 약 2분 39초, 실사용자라면 더 짧을 것).
- 홈 화면의 스트릭 카드(캐릭터 4단계 변화)는 감정적 자극이 있어 습관형성 앱 특유의 손맛이 있다. 외부 UX 리뷰 아티클도 이 지점("숏츠 볼 시간에 지식을 채우라"는 리마인드 푸시 포함)을 "위트있는 넛지(Nudge) UX"로 긍정 평가했다.
- 오답에 해설이 바로 붙어 있는 결과 화면은 복습 동기를 유발하기 좋은 구조다 — [AI 관찰]

**확인된 갭 (코드 기반 가설 → QA로 사실 확인됨)**
- **목표를 정리할 수 없음**: 삭제 불가·전환만 가능은 QA로 확인됨. 추가로 **전환 시 경고 없이 기존 목표가 즉시 사라진다**는, 가설보다 더 심각한 문제도 새로 발견됨(데이터 손실 위험 — [`feature-spec.md` §11-4](./feature-spec.md#11-알려진-이슈-및-기술부채)).
- **첫인상에서 이름이 불리지 않음**: 온보딩에 닉네임 입력 단계가 없다는 가설이 QA로 확인됨. 대신 OAuth 계정의 실명을 자동으로 가져와 "OOO 님 환영합니다!"로 표시한다는 것까지 구체적으로 밝혀짐.
- **오답을 다시 만날 방법이 없음**: 결과 화면에 "오답만 다시 풀기" 같은 즉시 재도전 CTA가 없음을 QA로 확인. 외부 아티클도 동일 지점(오답노트·복습 저장 기능 부재)을 독립적으로 지적해 근거가 이중으로 확보됨(§3-①).

**QA·아티클에서 새로 발견된 갭** (코드 분석만으로는 몰랐던 것)
- 홈 화면에서 스트릭이 오르는 바로 그 순간(퀴즈 완료 직후)에 카운터가 즉시 갱신되지 않아, 정작 성취 피드백이 가장 필요한 타이밍에 보이지 않는다 — [AI 관찰] 게이미피케이션 효과를 반감시키는 요소로 판단.
- 온보딩 카테고리 선택 라벨과 실제 저장 데이터가 다를 수 있는 버그([`feature-spec.md` §11-7](./feature-spec.md#11-알려진-이슈-및-기술부채))는, 만약 실제 Android 개발자가 "Android 개발"을 선택했는데 iOS 콘텐츠를 받는다면 **온보딩 직후 첫 학습 경험에서 바로 신뢰를 잃는** 치명적 리스크로 판단 — [AI 관찰]
- 리마인드 푸시가 항상 같은 문구라 시간이 지나면 스팸처럼 느껴질 수 있다는 지적(외부 아티클) — 사용자가 이미 로컬에서 개선에 착수함(§3-⑪).
- PDF 업로드 실패 시 유저가 더 진행할 방법이 없는 "막다른 길(Dead-end)"이라는 지적(외부 아티클; 이번 QA 라운드에서 실패 상황을 직접 재현하진 않았으나 코드 구조상 타당성이 높다고 판단) — 신규 제안 §3-⑩의 근거.
- **알림 시간이 출퇴근 2개로 고정**: 서현처럼 스케줄이 유동적인 직군에게는 경직적일 수 있음(코드 기반 가설, 이번 QA에서는 별도 검증 안 됨).

**여전히 미확인 — 다음 라운드 과제**
- 스트릭이 실제로 끊겼을 때 느끼는 감정(이번 QA는 1일차만 진행해 검증 불가).
- 게이미피케이션 요소·카피가 진짜로 "계속 쓰고 싶게" 만드는지는 AI가 대신 판단할 수 없는 영역 — 페르소나에 가까운 실제 인간 사용자의 리뷰가 필요.
- 성장 지표(정답률 추이 등)에 대한 니즈는 코드 기반 가설 단계에 머물러 있음(§3-③) — QA·아티클 어느 쪽에서도 직접 언급되지 않음.

## 3. 신규 기능 제안

> uibowl.io 아티클은 틈틈잇을 사례로 분석하며 "**데드엔드(Dead-end) 없는 설계**" — 기술적 실패나 제약이 생기더라도 유저의 학습 흐름이 끊기지 않도록 항상 대안 경로를 제공해야 한다는 원칙 — 을 핵심 인사이트로 짚었습니다. 아래 제안 중 특히 ①·⑩은 이 원칙을 구체화한 것입니다.

### A. 학습 지속력

**① 오답노트 & 간격반복 복습 큐 (Spaced Repetition)**
- 배경: 틀린 문제가 결과 화면 해설로 끝나고 다시 등장하지 않아 "안다고 착각"하기 쉽다.
- 설명: 오답을 자동으로 모아두고 2일·7일·14일 등 간격을 두고 1~3문항짜리 짧은 복습 세트로 재출제. 기존 "5분 이내" 세션 컨셉과 자연스럽게 결합.
- 기대효과: 장기 기억 정착률 향상, "이 앱을 쓰면 실제로 는다"는 체감 — 자기개발 페르소나의 핵심 니즈에 직접 대응.
- **근거 이중 확보**: uibowl.io 아티클이 동일 갭을 독립적으로 지적("문제를 푸는 것보다 중요한 건 틀린 것을 내 것으로 만드는 과정")했고, QA에서도 결과 화면에 "오답만 다시 풀기" 즉시 재도전 CTA가 없음을 확인 — 코드 기반 가설이 외부 리뷰·실기기 QA 양쪽에서 검증됨.

**② 스트릭 프리즈 (연속학습 보호권)**
- 배경: 현재 스트릭은 하루만 놓쳐도 끊기고 보호 수단이 없어, 이탈을 유발할 수 있는 구조다.
- 설명: 재화(§4) 소비 또는 특정 마일스톤 달성 시 자동 지급되는 아이템으로, 결석 하루를 보호해 스트릭을 유지.
- 기대효과: 스트릭 단절로 인한 이탈 완화. 재화 시스템의 자연스러운 첫 소비처.

**③ 주간/월간 학습 리포트**
- 배경: 스탬프·스트릭 숫자 외에 성장을 보여주는 지표가 없다.
- 설명: 주 단위로 학습일수·정답률 추이·카테고리별 강약점을 요약해 홈 또는 라이브러리에 노출.
- 기대효과: 성과 가시화를 통한 지속 동기부여, 공유 유도로 자연스럽게 이어짐(⑦과 연계).

### B. 목표/콘텐츠 관리

**④ 목표 보관·삭제 + 전환 시 확인 다이얼로그** ⚠️ 우선순위 최상위로 조정
- 배경: 현재 목표는 삭제가 불가능하고 전환만 가능해 목록이 계속 늘어난다. 더 심각하게는, **2026-07-24 QA로 확인된 바** 새 목표를 추가하면 진행 중이던 기존 목표가 **경고 없이 즉시 사라진다**([`feature-spec.md` §11-4](./feature-spec.md#11-알려진-이슈-및-기술부채)).
- 설명: (1) 목표 목록 화면에 "보관(숨김)" 또는 "삭제" 옵션 추가. (2) 홈의 "+" 새 목표 추가 시 진행 중인 목표가 있다면 "기존 목표는 어떻게 할까요? (계속 진행 / 새 목표로 전환)" 확인 다이얼로그를 반드시 거치도록 보강.
- 기대효과: 목록 관리 편의성 + 실수로 인한 학습 데이터 손실 방지. 코드 기반 가설 단계에서는 "불편함" 정도였으나, QA로 실제 데이터 손실 리스크가 확인되어 우선순위를 최상위로 조정.

**⑤ AI 약점 분석 피드백**
- 배경: 이미 서버가 LLM으로 요약·퀴즈를 생성 중이라 오답 패턴 분석도 같은 인프라로 확장 가능.
- 설명: 퀴즈 결과 화면에 "오늘의 한 줄 피드백"(예: "OO 개념에서 자주 틀려요, 내일은 이 부분을 우선 볼까요?")을 AI가 생성해 노출.
- 기대효과: 콘텐츠가 나에게 맞춰지고 있다는 느낌 강화, 오답노트(①)와 결합 시 시너지.

**⑩ PDF 업로드 실패 시 텍스트 직접입력 폴백** *(외부 UX 리뷰 근거)*
- 배경: 업로드가 실패하면(서버 오류, 파일 형식 문제 등) 유저가 더 진행할 방법이 없는 "막다른 길"에 놓인다. 학습 의지를 갖고 들어온 유저에게 기술적 오류는 이탈의 가장 큰 원인 중 하나가 될 수 있다.
- 설명: 업로드 실패 시(또는 업로드 대신 처음부터) 유저가 미리 정리해둔 텍스트를 직접 입력창에 붙여넣으면, AI가 그 텍스트를 분석해 학습 콘텐츠를 생성하는 대체 경로 제공.
- 기대효과: 기술적 한계를 사용자 선택권으로 보완 — "데드엔드 없는 설계" 원칙의 핵심 적용 사례.

### C. 동기부여/게이미피케이션

**⑥ 뱃지 컬렉션(도감)**
- 배경: 현재 마일스톤 보상은 스트릭 카드 이미지 변화뿐, 수집 요소가 없다.
- 설명: 7일/30일/100일 연속 학습, 특정 카테고리 100문제 등 마일스톤 달성 시 뱃지를 지급하고 도감 형태로 모아보기 제공.
- 기대효과: "완성하고 싶은 욕구" 자극을 통한 장기 리텐션.

**⑦ 성취 공유 카드**
- 배경: 자기개발 콘텐츠는 SNS 인증샷 공유로 확산되는 경우가 많은데 현재 공유 기능이 없다.
- 설명: 스트릭·스탬프 현황을 이미지 카드로 내보내 SNS 공유.
- 기대효과: 자연스러운 바이럴 유입과 사용자의 자기 인증(accountability) 욕구 충족.

### D. 소셜/도달성

**⑧ 친구 초대 & 스터디메이트 랭킹(옵트인)**
- 배경: 현재 완전히 개인화된 1인 경험만 존재. 자기개발 앱에서는 약한 사회적 압박이 지속률을 크게 높인다(챌린저스류 사례).
- 설명: 친구 초대 시 양쪽에 재화 보상 지급, 초대한 친구들 사이에서만 보이는 주간 학습량 랭킹(옵트인, 전체 공개 랭킹 아님).
- 기대효과: 리퍼럴을 통한 자연 유입 + 사회적 동기부여.

**⑨ 홈 화면 위젯**
- 배경: "5분 이내, 틈새시간"이 핵심 가치인데 현재는 앱을 열어야만 학습 상태를 확인할 수 있다.
- 설명: 오늘의 학습 상태·스트릭을 보여주는 홈 화면 위젯 제공, 탭하면 바로 요약/퀴즈로 진입.
- 기대효과: 앱 진입 마찰 감소로 "틈새시간" 포지셔닝 강화.

### E. 리텐션 / UX 라이팅

**⑪ 요일·연속학습일수별 개인화 리마인드 메시지** *(진행중 — 사용자가 로컬에서 이미 착수)*
- 배경: 리마인드 푸시가 항상 동일한 문구라 시간이 지나면 스팸처럼 느껴져 무시되기 쉽다(외부 UX 리뷰 지적. 참고로 현재 리마인드 푸시 자체는 "숏츠 볼 시간에 지식을 채우라"는 위트있는 문구로 이미 좋은 평가를 받고 있음 — 문제는 다양성 부족).
- 설명: 요일(예: 월요일 "월요병을 이기는 퀴즈 한 입!")이나 연속 학습일수(예: 5일차 "벌써 5일째예요! 열정이 대단해요!")에 따라 다양한 문구를 노출.
- 기대효과: 알림이 "스팸"이 아닌 "대화"처럼 느껴지게 해 진입률 개선. **사용자가 이미 로컬 환경에서 이 방향으로 개선에 착수함** — 구현이 완료되면 이 항목은 "제안"에서 "적용 완료"로 갱신 필요(이번 문서에서는 구체적인 diff를 확인하지 못해 "제안"으로 유지).

## 4. 인앱 재화 시스템 설계: "알갱이" (가칭)

기존 "쿠폰"(당일 1회용, 이월/누적 불가)을 정식 재화로 확장하는 개념입니다. 이름은 홈 화면의 간식 캐릭터 은유("조금씩 모아 먹는다")와 연결해 **"알갱이"**로 예시를 들었으며, 최종 네이밍은 디자인/브랜드 결정이 필요합니다.

> **명확히 함**: 이 제안은 Google Play Billing·구독·인앱결제(IAP) 등 **실 결제를 도입하지 않습니다.** 아래 소비처는 전부 학습 행동으로 획득하는 "알갱이"로만 구매 가능하도록 설계해, 수익화 압박 없이 참여·재방문을 유도하는 데 초점을 맞췄습니다.

### 획득 경로
| 획득 조건 | 비고 |
|---|---|
| 일일 학습(요약+퀴즈 세트) 완주 | 매일 고정 지급 |
| 정답률 100% 보너스 | 완주 지급분에 추가 |
| 스트릭 마일스톤(7·30·100일) | 1회성 큰 보상 |
| 주간 챌린지 달성(예: 주 5일 이상 학습) | 주간 보상 |
| 오답노트 복습 완료(제안 ①) | 복습 습관 형성 유도 목적의 소량 지급 |
| 친구 초대 성공(가입+온보딩완료) | 초대자·피초대자 양쪽 지급 |
| 보상형 광고 시청 | 기존 "쿠폰" 지급을 알갱이 지급으로 통합(광고 시청 자체는 유지) |

### 소비처 — 결제형 아이디어를 재화로 치환한 목록
| 소비처 | 내용 |
|---|---|
| 추가 학습권 | 기존 "쿠폰" 기능을 광고 시청 없이 알갱이로 즉시 구매 |
| 스트릭 프리즈(제안 ②) | 결석 하루 보호 |
| PDF 업로드 슬롯 추가 | 월 기본 제공량 초과 시 알갱이로 추가 슬롯 구매 |
| 프리미엄 심화 카테고리 언락 | 난이도 높은 심화 콘텐츠 카테고리 잠금 해제 |
| 광고 스킵권(기간제) | 예: 7일간 광고 시청 없이 추가 학습권 자동 지급 |
| 캐릭터/홈 화면 테마 꾸미기 | 홈 화면 간식 캐릭터 스킨, 배경 테마 등 코스메틱 아이템 |
| AI 피드백 상세 리포트 언락 | 제안 ③·⑤의 기본 버전은 무료, 심화 버전은 알갱이로 해제 |

## 5. 우선순위 총평

정성적 평가이며, 실제 스프린트 계획 시 재산정이 필요합니다. QA로 실사용 리스크가 확인된 ④는 이번 갱신에서 최상위로 조정했습니다.

- **최상위 (QA로 데이터 손실 리스크 확인)**: ④ 목표 보관·삭제 + 전환 확인 다이얼로그
- **저난이도 · 고가치**: ① 오답노트(외부 검증 + QA 이중 근거), ② 스트릭 프리즈
- **중난이도**: ③ 주간 리포트, ⑤ AI 약점 피드백, ⑥ 뱃지 컬렉션, ⑨ 홈 위젯, ⑩ 업로드 실패 텍스트 폴백
- **진행 상황 확인 필요**: ⑪ 개인화 리마인드 메시지 — 사용자가 로컬에서 이미 착수, 완료 여부에 따라 "적용 완료"로 재분류 필요
- **고난이도 / 별도 스프린트급**: ⑧ 소셜·랭킹(친구 관계 데이터 모델 신규 필요), "알갱이" 재화 시스템 전체 도입(적립·소비 트랜잭션 설계, 부정사용 방지 등 인프라 필요)

## 6. 부록: 개선 권장 사항

새 기능은 아니지만 조사·QA 중 발견해 함께 남깁니다(상세는 [`feature-spec.md` §11](./feature-spec.md#11-알려진-이슈-및-기술부채) 참고).

- 온보딩 중 닉네임을 입력할 방법이 없음(연결되지 않은 화면) — 첫 진입 개인화 인상에 영향.
- 목표 만료 안내가 전용 화면 없이 홈 다이얼로그로만 처리됨 — 더 명확한 안내가 필요하다면 전용 화면 재도입 검토.
- **(2026-07-24 QA 신규 발견)** 온보딩 카테고리 선택 라벨과 실제 저장 데이터가 불일치하는 버그 — 신뢰도에 직접 영향을 주는 만큼 우선 수정을 권장.
- **(QA 신규 발견)** 알림 권한 체크박스가 OS 권한 상태와 실시간 동기화되지 않음(앱 재시작 필요).
- **(QA 신규 발견)** 홈 화면 스트릭 카운터가 퀴즈 완료 직후 즉시 갱신되지 않음(라이브러리 탭 이동 시에만 반영).
- **(QA 신규 발견, 경미)** 요약 스트리밍 중 일시적 띄어쓰기 누락, 마이페이지 초기 로딩 스피너 부재.

### 아직 확보하지 못한 것
- **진짜 인간 사용자의 주관적 피드백**: 이번 QA는 AI가 기기를 조작한 것이라, "동기부여가 되는가", "스트릭이 끊겼을 때 기분이 어떤가" 같은 원래 요청의 핵심(자기개발 욕구가 큰 유저의 실제 반응)은 아직 확보되지 않았습니다. 사용자 본인 또는 페르소나에 가까운 실제 사용자의 리뷰가 다음 라운드 과제로 남아있습니다.
